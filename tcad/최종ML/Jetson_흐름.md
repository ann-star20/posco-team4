# Jetson에서 두 모델이 돌아가는 흐름

모든 시간은 개발용 PC(CPU 8코어) 측정이다. **Jetson Orin Nano 실측은 아직 없다** (`jetson_벤치.py`로 재서 채울 것).

## 1. 두 모델의 역할

| | 기본 모드 (2단 GP) | 고정밀 모드 (GP + TabPFN 가중 평균) |
|---|---|---|
| 한 줄 | 모든 후보를 빠르게 훑는 탐색용 | 남은 후보를 정밀하게 다시 확인하는 확인용 |
| 코드 | `2단_GP.py` (`Surrogate`) | `고정밀.py` (`HighPrecision`) |
| 필요한 것 | NumPy, `모델/gp.npz` (0.9 MB) | + torch, tabpfn 9.x, `모델/tabpfn/…ckpt` (44 MB), `모델/학습배열.npz` |
| 속도 (PC CPU) | 3만 후보 1.4초, 10만 후보 5~8초 | 호출당 고정 약 6초 + 점당 약 0.03초 (후보 20개 약 9초, 100개 약 9초) |
| 정확도 (학습 영역 안) | Vth 2.2 mV, gm 0.55 %, Id 0.99 %, BV 0.157 V | Vth 2.2 mV, gm 0.55 %, Id 1.0 %, **BV 0.126 V** |
| 불확실도 | 보정 후 2σ 포함 94~98 % | 고정밀 전용 보정 배율 적용 (`결과/고정밀평가.md`) |
| 계산 장치 | **CPU, float64** (float32로 내리면 어긋남) | GPU 또는 CPU (torch) |
| 없을 때 | 필수 | 없으면 자동으로 기본 모드로 대체 |

두 모델은 같은 노브 입력과 같은 영역 규칙(`in_domain`)을 쓰고, 영역 밖 입력에는 값을 내지 않는다(NaN).

## 2. 전체 흐름 (진단 한 번)

```
 Unity / 측정 입력
   Vth, gm, Id, (BV), 웨이퍼 수 N
          │
          ▼
 ┌─────────────────────────────────────────────┐
 │ ① 기본 모드: 2단 GP (Jetson CPU, float64)       │
 │   후보 격자 수만 개를 in_domain 안에서 만든다      │
 │   TwoStagePipeline.fast_predict(후보)           │
 │   → 후보마다 예측 4개 + 보정된 σ                   │
 │   → 측정값과 비교한 점수(가능도) → 사후분포         │
 │   소요: 3만 후보 약 1.4초 / 7만 후보 약 4초 (PC)    │
 └─────────────────────────────────────────────┘
          │ 확률 높은 상위 K개 후보 (K ≤ 100, 예: 20)
          ▼
 ┌─────────────────────────────────────────────┐
 │ ② 고정밀 모드: GP + TabPFN (Jetson GPU 권장)     │
 │   TwoStagePipeline.refine(상위 K개)             │
 │   → GP 와 TabPFN 을 σ 역제곱 가중 평균            │
 │   → 후보 K개의 예측·σ 를 더 정확하게               │
 │   → K개 안에서 사후분포 다시 계산                  │
 │   소요: 호출당 약 6초 + 점당 0.03초 (PC CPU)       │
 └─────────────────────────────────────────────┘
          │  (고정밀을 쓸 수 없으면 ①의 결과를 그대로 사용, 모드 표시에 사유가 남는다)
          ▼
 판정: 가장 유력한 원인 노브 또는 "구분 불가", 다음 측정 권고(BV 등)
          │
          ▼
 보정안 (도즈·산화막 조정, 에피는 제어 불가)
          │
          ▼
 TCAD 확인 (서버/PC, 수십 분, PostgreSQL 작업 큐로 비동기)
          │
          ▼
 결과를 Unity 로 전달
```

## 3. 언제 어느 모드를 쓰는가 (권장 정책)

1. **탐색과 사후분포 계산은 항상 기본 모드**다. 후보가 수만 개라 고정밀은 쓸 수 없다 (TabPFN 은 PC에서 1만 점에 약 9분).
2. **고정밀은 확인 단계에서만** 쓴다: 보정안을 만들기 직전이나 결과를 사용자에게 보고하기 직전, 또는 유력 후보 둘의 확률이 비슷해 판정이 경계에 있을 때.
3. 고정밀에 넘기는 후보는 **사후 확률 상위 K개 (K ≤ 100)**. K 가 20이든 100이든 시간 차이는 거의 없으니 넉넉히 잡아도 된다 (호출당 고정 비용이 지배).
4. **자동 대체**: torch·tabpfn·가중치가 없거나 오류가 나면 `TwoStagePipeline` 이 기본 모드로 돌아가고 `result["mode"]`에 이유를 적는다. 진단은 중단되지 않는다.
5. (진단 에이전트에서 구현할 것) 고정밀 호출에 시간 제한(예: 20초)을 두고 넘으면 기본 모드 결과를 쓴다.

## 4. 코드에서의 사용

```python
from ml_파이프라인 import TwoStagePipeline    # 파일 이름이 바뀌었다면 importlib 로
p = TwoStagePipeline()                         # 고정밀을 쓸 수 있으면 함께 불러온다 (high_precision=False 로 끌 수 있다)
r1 = p.fast_predict(후보들)                    # ① 기본 모드: (n,3) [도즈, 에피, 산화막] -> vth, gm, id4v, bv, sigma_*, in_domain
r2 = p.refine(상위후보)                        # ② 고정밀 모드 (없으면 기본으로 대체), r2["mode"] 에 사용한 모드
python ml_파이프라인.py                        # 흐름 시연과 시간 측정
```

## 5. Jetson 설치 체크리스트
1. 복사: `2단_GP.py`, `고정밀.py`, `ml_파이프라인.py`, `jetson_벤치.py`, `jetson_검증.py`, `테스트/`, `모델/` 전체.
2. 기본 모드만: `pip install numpy`. 이것으로 `python 2단_GP.py`, `python jetson_벤치.py` 확인.
3. 고정밀 모드까지: JetPack 에 맞는 **NVIDIA 제공 torch 휠**을 설치하고 `pip install tabpfn==9.2.0`. 이 조합은 Jetson 에서 아직 시험하지 못했다. 설치가 안 되면 기본 모드만으로도 시스템은 동작한다.
4. `python jetson_검증.py` 로 100점 검증 (PC 값과 일치, 영역 밖 NaN, 고정밀 동작). "== 전체 판정: 모두 통과" 가 나오면 정상. `python jetson_벤치.py` 로 속도 기록, `python ml_파이프라인.py` 로 두 모드 흐름 확인.

## 6. 알려진 한계
- Jetson 속도, torch/tabpfn 설치 가능 여부는 미확인.
- 고정밀의 이득은 주로 BV 정확도(0.157 → 0.126 V)와 Id 불확실도 보정이고, Vth·gm 은 같다. 교차검증 1회 결과이며 에피 감소 방향 영역 밖 외삽에서는 두 모드 모두 크게 틀린다 (영역 밖은 쓰지 않는다).
- 고정밀의 σ 는 교차검증으로 구한 보정 배율을 쓴다. 데이터가 바뀌면 `python 고정밀_점검.py` 로 다시 구한다.
- TCAD 합성 데이터로 학습했고 측정 잡음·공정 산포는 가정값이다.
