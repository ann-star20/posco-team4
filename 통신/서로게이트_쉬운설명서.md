# 서로게이트 모델 쉬운 설명서 (팀원용)

수식과 전문 용어는 최소로 쓰고, 비유와 실제 숫자로 설명한다. 모든 수치는 이 프로젝트의 평가 결과 파일에서 가져왔다 (출처는 맨 아래).

---

## 0. 한 줄 요약

> 공정 변수 3개(도즈, 에피 도핑, 산화막 두께)를 넣으면, **TCAD를 돌리지 않고** 소자 특성 4개(Vth, gm, Id(4V), BV)를 **1천분의 1초 안에 예측**하고, **그 예측을 얼마나 믿어도 되는지**까지 같이 알려 주는 모델이다. 학습하지 않은 범위의 입력은 값을 주지 않고 거절한다.

---

## 1. 무엇을 넣고 무엇이 나오나

| | 항목 | 단위 | 기준값 |
|---|---|---|---|
| 입력 | 바디 도즈 `body_dose` | cm⁻² | 7.7e12 |
| 입력 | 에피 도핑 `epi_doping` | cm⁻³ | 1.7e16 |
| 입력 | 게이트 산화막 두께 `oxide_thickness` | µm | 0.06 |
| 출력 | 문턱전압 `vth` | V | 2.26 |
| 출력 | 트랜스컨덕턴스 `gm` | µS/µm | 4.60 |
| 출력 | 게이트 4 V에서 드레인 전류 `id_on` | µA/µm | 5.21 |
| 출력 | 항복전압 `bv` | V | 41.1 |

기준값을 넣으면 오른쪽 기준값의 특성이 나온다. 입력을 바꾸면 출력이 어떻게 변하는지를 예측하는 것이 서로게이트의 일이다.

---

## 2. 왜 필요한가

TCAD로 소자 하나를 계산하면 약 30분이 걸린다 (전류 곡선 약 8분 + 항복전압 약 20분). 진단 에이전트는 "원인 후보 수만 개"를 시험해 봐야 하므로 TCAD로는 불가능하다. 서로게이트는 TCAD 결과를 미리 모아 두었다가 흉내 내는 **빠른 계산기**다. Jetson에서 1점 예측이 약 1 ms (HTTP 응답 포함 약 6 ms)이다.

---

## 3. 어떻게 예측하나: "관측소 사이의 기온" 비유

TCAD로 계산해 둔 **185개 샘플**(공정값과 결과 쌍)이 학습 데이터다. 새 공정값이 들어오면:

- 가장 비슷한 샘플 하나를 골라 그 값을 쓰는 방식(SQL의 select)이 아니다. 샘플은 185개뿐이라 대부분의 입력은 샘플 사이에 있어서 틀린다.
- 대신 **185개 샘플을 모두 쓰되, 가까운 샘플의 영향을 크게, 먼 샘플은 작게** 반영해서 부드러운 곡선을 그린다. 기상 관측소 두 곳의 기온으로 그 사이 지점의 기온을 추정하는 것과 같다.

이 방식의 모델을 **가우시안 프로세스(GP)**라고 한다. 이름은 몰라도 된다.

GP의 좋은 점은 **예측값과 함께 "얼마나 믿을지"가 자동으로 나온다**는 것이다. 샘플이 가까이 있으면 믿을 만하고, 샘플에서 멀면 "나도 잘 모르겠다"가 된다.

---

## 4. 모델이 4개인 이유 ("2단"이 뜻하는 것)

특성마다 따로 학습한 작은 모델이 하나씩, 모두 4개다.

| 모델 | 예측하는 것 | 받는 입력 |
|---|---|---|
| ① | Vth | 공정 3개 |
| ② | gm | 공정 3개 |
| ③ | Id(4V) | 공정 3개 **+ ①이 예측한 Vth** |
| ④ | BV | 공정 3개 |

Id(4V)는 Vth와 거의 한 몸처럼 움직인다 (학습 데이터에서 상관 −0.95). 그래서 ③은 Vth 예측을 힌트로 받는다. 그래서 "2단"이다 (1단: ①②④, 2단: ③).

**API 사용자(팀원)가 알아야 할 것은 하나뿐이다: 입력은 항상 공정 3개이고, 서비스가 위 4개를 전부 알아서 돌린다.** 4번째 입력(Vth)을 보내지 않는다.

---

## 5. 입력을 "비율"로 바꾸는 이유

서비스 안에서 입력을 기준값으로 나눈다.

| 공정 | 기준값 | 실제 값 | 비율 |
|---|---|---|---|
| 도즈 | 7.7e12 | 8.855e12 | 1.15 (15 % 많음) |
| 산화막 | 0.06 | 0.054 | 0.90 (10 % 얇음) |

정보는 하나도 없어지지 않는다. 단위만 바뀐다. 이유는 세 입력의 크기가 너무 다르기 때문이다 (1e12, 1e16, 0.06). 모두 1 근처 숫자로 맞추면 모델이 "어느 입력이 얼마나 중요한지"를 학습하기 쉽다. 이 변환은 **서비스 안에서만** 일어나고, API는 실제 물리 단위를 그대로 쓴다.

---

## 6. "불확실도"와 "보정 배율"

### 6-1. 불확실도 σ (시그마)
모델은 예측과 함께 "나는 이 정도 틀릴 수 있다"를 같이 낸다. 일기예보에 비유하면:

- 나쁜 예보: "내일 20 °C"
- 좋은 예보: "내일 20 °C, 오차는 ±1 °C 정도"

응답의 `metadata.sigma`가 이 값이다. 이 값을 어디에 쓰나:

- **진단**: 측정값과 예측을 비교할 때 믿을 만한 예측을 더 무겁게 본다.
- **보정이 맞을 확률**: "보정하면 규격 안에 들 확률 99 %"는 σ가 있어야 계산된다.
- **경고**: 학습 샘플에서 멀수록 σ가 커져서 "여기는 잘 모른다"를 알려 준다.

### 6-2. 보정 배율: "모델이 말한 오차가 진짜 오차와 맞는가"
모델이 "±0.6 %"라고 말했는데 실제로는 평균 1.0 %씩 틀리면, 모델은 **자신감이 과한** 것이다. 이를 고치는 방법:

1. 학습 데이터의 일부를 숨기고, 모델에게 예측하게 한다 (교차검증, 아래 설명).
2. 실제 오차와 모델이 말한 σ를 비교한다. 실제 오차 ÷ σ 를 구한다.
3. 이 비율이 평균적으로 1이면 모델이 정직하다. 1.7이면 실제 오차가 σ의 1.7배이므로 σ에 1.7을 곱해서 실제 오차에 맞춘다. 이 숫자가 "보정 배율"이다.

우리 결과: Vth 1.0, gm 1.0 (이미 정직), Id 1.70, BV 1.68 (자신감이 과해서 키웠다). 응답의 `sigma`는 이미 이 배율을 곱한 값이라, 팀원이 다시 곱할 필요 없다.

### 6-3. 교차검증이란
데이터를 5조각으로 나눠 4조각으로 학습하고 나머지 1조각으로 시험한다. 이것을 조각을 바꿔 5번 한다. 학습에 쓴 데이터로 시험하면 점수가 부풀려지므로, **모든 샘플이 한 번씩 "처음 보는 샘플"로 시험받게 하는** 정직한 평가 방법이다. 이 프로젝트는 분할을 바꿔 3회 반복했다.

---

## 7. 학습하지 않은 범위는 거절한다 (`OUT_OF_DOMAIN`)

모델은 학습한 범위에서만 믿을 수 있다. 범위 밖 입력은 **값을 주지 않고** `OUT_OF_DOMAIN`으로 돌려보낸다 (HTTP 200, `status: failed`). 단위를 잘못 보낸 경우도 여기서 걸린다.

- **코어**: 세 입력이 모두 기준값의 ±30 % 안. 학습 샘플이 가장 많은 구간.
- **한 변수만 확장**: 한 변수만 ±30 %를 넘고 그 변수의 검증 범위(도즈 0.7~1.7, 에피 0.3~1.7, 산화막 0.5~1.4) 안일 때. 변수 둘 이상이 동시에 넘는 구석은 검증한 적이 없어서 제외.
- **punch-through 구석 제외**: 도즈가 0.80 미만이고 에피가 1.40 초과인 구석. 학습에 쓰지 않은 샘플로 검증하다가 이 구석에서 BV 예측이 크게 틀리는 것을 발견했다 (예: 예측 34.7 V, 실제 21.9 V). 모델이 못 맞추는 구석이라서 영역에서 빼고 거절하도록 했다.

## 8. API로 보면

요청:
```json
{"task_type": "surrogate", "model_contract_version": "fab-ml-v1",
 "input_payload": {"process_parameters": {"body_dose": 7.7e12, "epi_doping": 1.7e16, "oxide_thickness": 0.06}}}
```
응답에서 볼 것:

| 필드 | 뜻 |
|---|---|
| `result_payload.vth / gm / id_on / bv` | 예측값 (V, µS/µm, µA/µm, V) |
| `metadata.sigma` | 각 값의 불확실도 (이미 보정 배율 적용) |
| `metadata.in_domain` | 학습 범위 안인지 |
| `metadata.input_ratios` | 서비스가 계산한 비율 (참고용) |
| `status: failed` + `error_code: OUT_OF_DOMAIN` | 범위 밖 입력 |

예시 파일: `통신/예시/1_surrogate_기준값.json`, `2_surrogate_영역밖_계약예시숫자.json`.

## 9. 성능 지표: 무엇을 어떻게 재나

### 9-1. 용어
| 용어 | 뜻 | 쉬운 말 |
|---|---|---|
| RMSE | 오차를 제곱해 평균하고 루트 | "보통 이 정도 틀린다" (큰 오차를 더 무겁게 봄) |
| MAE | 오차 절댓값의 평균 | "평균적으로 이 정도 틀린다" |
| 95 % 분위 | 오차가 작은 쪽부터 95 %가 이 값 이하 | "거의 모든 경우 이 이내" |
| 최대 오차 | 가장 크게 틀린 경우 | "최악의 경우" |
| R² | 1에 가까울수록 변화를 잘 따라감 | "곡선이 얼마나 맞는가" |
| 2σ 커버리지 | 실제 값이 예측±2σ 안에 든 비율. 이상적으로 약 95 % | "모델의 불확실도가 정직한가" |

### 9-2. 결과 (교차검증, 학습 영역 안)
| 출력 | 평가 샘플 수 | RMSE | MAE | 95 % 분위 | 최대 오차 | 목표 | 2σ 커버리지 |
|---|---|---|---|---|---|---|---|
| Vth | 143 | **2.19 mV** | 1.54 mV | 3.84 mV | 15.7 mV | 25 mV | 97.9 % |
| gm | 143 | **0.56 %** | 0.45 % | 1.07 % | 1.73 % | 2.5 % | 97.2 % |
| Id(4V) | 143 | **1.02 %** | 0.27 % | 0.93 % | 8.85 % | 2.5 % | 94.1 % |
| BV | 64 | **0.156 V** | 0.091 V | 0.40 V | 0.53 V | 0.15 V | 93.8 % |

해석:
- Vth는 규격 폭(1.7~2.6 V = 900 mV)에 비해 오차가 2 mV 수준이다.
- gm과 Id는 1 % 안팎이다. Id의 최대 오차 8.85 %는 소자가 거의 꺼져 있는 극단 샘플에서 난 것이다.
- BV는 목표 0.15 V에 **아주 조금 못 미친다** (0.156 V). 숨기지 않고 말한다.
- 2σ 커버리지가 93.8~97.9 %로 이상적인 95 %에 가깝다. 모델이 말하는 불확실도가 실제와 맞는다.

### 9-3. 규격 합격·불합격 판정 정확도
교차검증 예측으로 규격(Vth 1.7~2.6 V, BV 40 V 이상)을 판정했을 때, Vth는 143개 중 143개, BV는 64개 중 64개를 맞혔다 (경계 근처 오판 없음).

### 9-4. 구간별 차이
코어(기준값 ±30 %)에서 오차가 작고 영역 가장자리에서 커진다. 예: Vth 1.5 mV (코어) 대 3.0 mV (확장), BV 0.02 V 대 0.24 V. 가장자리 쪽 답을 덜 믿어야 하는 이유다. (구간별 수치는 `성능보고서.md`의 이전 평가 기준이라, 전체 BV 오차가 위 표의 최종 모델 값보다 크게 나온다. 코어가 가장자리보다 정확하다는 경향이 요점이다.)

### 9-5. 속도
Jetson CPU에서 1점 0.86 ms, 1만 점 0.49초, HTTP 응답 6 ms. TCAD 약 30분과 비교하면 수십만 배 빠르다.

## 10. 이 모델을 믿어도 되는 이유 (사람들에게 말할 근거)

1. **처음 보는 데이터로 쟀다.** 학습에 쓰지 않은 샘플로 5-겹 교차검증을 3회 반복했고, 학습 도중에 보지 않은 두 번째 TCAD 배치로도 검증했다. 학습 점수를 부풀리지 않았다.
2. **오차가 규격 폭에 비해 작다.** Vth 2 mV 대 규격 폭 900 mV. 합격·불합격 판정은 교차검증에서 모두 맞았다.
3. **불확실도가 정직하다.** 모델이 말하는 오차(σ)가 실제 오차와 맞도록 보정했고, 2σ 커버리지가 약 95 %다.
4. **모르는 것은 거절한다.** 학습하지 않은 범위는 값을 주지 않고 `OUT_OF_DOMAIN`으로 돌려보낸다. 검증 중 발견한 약점(punch-through 구석)은 숨기지 않고 영역에서 제외했다.
5. **여러 모델을 비교해 골랐다.** 선형, 다항, GP, MLP 앙상블, LightGBM, TabPFN 등 16개 모델을 같은 데이터·같은 분할로 비교해 2단 GP를 선택했다. 비교 기록: `ML/ML 비교/결과/비교결과.md`, 과적합 비교 `과적합.md`, 초기 5개 후보 비교 `ML/간의_TCAD_GP/결과/서로게이트평가.md`.
6. **서비스로 검증했다.** 자체 시험 52개 항목과 Worker 대역 시험이 통과했고, Jetson에서 서비스가 부팅 시 자동 시작되어 동작한다.

### 말하면 안 되는 것 (정직하게)
- "실제 공정에서 이 정확도가 나온다." → 학습·검증 데이터가 모두 TCAD 합성 데이터이고 측정 잡음도 가정값이다. 실측 검증은 아직 하지 않았다.
- "TCAD를 대체한다." → TCAD를 흉내 내는 빠른 근사다. 중요한 결정(보정 적용)은 TCAD 검증과 관리자 승인을 거친다.
- "모든 입력에서 정확하다." → 학습 영역 안에서만 유효하다.

### 한계 (질문받으면 먼저 말하는 편이 신뢰를 준다)
1. 학습 데이터가 TCAD 합성 데이터 185점이다 (BV는 88점).
2. BV 오차가 목표(0.15 V)에 약간 못 미친다 (0.156 V).
3. Id의 최대 오차가 8.85 %이다 (거의 꺼진 극단 샘플).
4. 영역 가장자리에서 오차가 커진다.
5. TCAD 자체도 실제 소자의 모델일 뿐이다.

### 발표용 한 문장
> "TCAD 185개를 학습해 소자 특성 4개를 1 ms에 예측하며, 보지 않은 데이터에서 Vth 오차 2 mV, gm·Id 1 % 수준이고, 예측과 함께 신뢰 정도를 내며, 학습하지 않은 범위는 스스로 거절합니다. 실측 검증은 다음 단계입니다."

| 왜 신경망이 아니라 GP인가 | 샘플이 185개뿐이라 적은 데이터에서 잘 맞고, 불확실도가 자동으로 나오기 때문. 같은 데이터·같은 분할로 16개 모델을 비교했다 (`ML/ML 비교/결과/비교결과.md`). 교차검증 RMSE: 2단 GP는 Vth 2.19 mV·gm 0.56 %·Id 1.01 %·BV 0.16~0.18 V, MLP 앙상블은 4.54 mV·1.31 %·5.30 %·0.66 V, LightGBM은 107.77 mV·3.82 %·58.3 %·2.43 V, TabPFN v2는 5.56 mV·0.59 %·9.19 %·0.26 V. Id(4V)에서 격차가 가장 크다 |
| 두 가지 이상의 공정이 섞여 생기는 불량은 | 다룬다. 모델 4개는 **출력**(Vth, gm, Id, BV)마다 하나씩이고, 각 모델은 **공정 3개를 한꺼번에** 입력받는다. 학습 샘플의 대부분(대량 실행 146개)도 세 공정이 동시에 바뀐 조합이다. 진단은 8가지 원인 조합(정상, 도즈, 에피, 산화막, 도즈+에피 등)을 모두 후보로 둔다. 다만 변수 둘 이상이 동시에 ±30 %를 넘는 구석은 검증하지 않아 거절한다 |
| TCAD 검증 요청은 누가 보내나 | 모델 서비스도 Unity도 아니다. 모델 서비스는 응답에 `compensation.route`와 `tcad_proposal`만 담아 돌려준다. 그것을 받은 **Gateway**가 `route`가 `tcad_verify`일 때 TCAD 워크스테이션에 HTTP 요청을 보낸다. Unity는 Gateway와만 통신한다 |
| 학습 데이터에 없는 값은 | 범위 안이면 샘플 사이를 부드럽게 연결해 예측하고, 범위 밖이면 거절한다 |
| 실제 소자와 맞나 | 아직 모른다. 합성 데이터로 학습했고 실측 비교는 다음 단계다 |
| 예측이 틀리면 어떻게 | 응답의 σ가 커지거나 `in_domain`이 false가 된다. 보정은 TCAD 검증과 관리자 승인을 거친다 |
| 새 데이터가 생기면 | `최종ML만들기.py`로 다시 학습하고 `모델/`을 교체한다 |
