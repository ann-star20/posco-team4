# OHT 공정 이송 애니메이션

## 실행

`MOSFETSmallFab_Corrected` 씬에서 Play → 하단 `OHT 이송` → `Start / Restart`.
Play 진입만으로는 운반을 시작하지 않는다. `Pause / Resume`와 OHT 추적 카메라 전환을 제공한다.

평소에는 각 설비의 FOUP과 개별 시작 버튼을 사용할 수 있다. OHT 연속 시퀀스 실행 중에만 개별 설비를 도착 대기로 전환한다. 개별 설비 동작 중에는 OHT가 시작되지 않으며, OHT 시퀀스 완료 후에는 개별 실행이 다시 가능하다. LOT HOLD 판정은 이 모드 전환으로 해제하지 않는다.

## 동작 순서

스토커 슬롯 1에서 포크로 꺼내 I/O에 출고 → OHT 픽업 → 산화로 로딩부 안착 → 기존 산화·웨이퍼 회수·도어 닫힘 완료 → 픽업 → 엘립소미터 안착·측정·회수 → PASS 확인 → 이온주입기 안착·주입·회수 → 픽업 → 순환 레일을 따라 스토커 I/O로 복귀 → 포크로 예약 슬롯 1에 입고.

측정 FAIL은 LOT HOLD로 남는다. FOUP을 계측기에 유지하고 이동과 이온주입을 차단한다. 엘립소미터 탭에서 재측정 PASS 후 검토 승인해야 이송이 이어진다. 단순 PASS 재측정으로 기존 HOLD를 자동 해제하지 않는다.

## 구현 범위

- Blender의 폐곡선 중심점 JSON을 거리 기준으로 따라간다. 새 Splines 패키지는 설치하지 않는다.
- 이동 중 승강 프레임을 완전히 수납하고 FOUP을 그리퍼에 연결한다. 안착 시 로드포트로 부모를 변경한다.
- 승강 시 2개 벨트의 길이·각도를 갱신하고 그리퍼를 개폐한다.
- 기존 설비 로봇·웨이퍼·도어 애니메이션을 보존한다. 운반용 FOUP과 각 설비 FOUP은 같은 `carrier_id`의 구간별 표시 모델이다. 안착·픽업 시 표시 소유권을 교대하며, 동일한 웨이퍼 GameObject가 설비 사이를 통과하는 구현은 아니다.
- 시작 FOUP은 슬롯 1에 보관되어 있다. 스토커 출고·OHT 회수·공정·반환·입고가 자동 연결된다. 스토커 내부에서는 동일한 운반 FOUP 객체를 실제로 포크·I/O·OHT 사이에서 전달한다. 슬롯 1은 출고 후 반환 전까지 예약하며, 예시 FOUP 두 개는 다른 슬롯에 보관한다.
- 공정값은 기존 DEMO 데이터다. TCAD·Jetson·ROS2 명령과는 새로 연결하지 않았다.

## 검증

`OhtFabSetup.once`로 기존 씬을 백업하고 설치한다. `OhtFabPlay.once`는 Play에서 전체 경로 두 번, 일시 정지, 그립·도크 오차 2mm 이내, 웨이퍼 복귀와 닫힌 도어 이후 회수, HOLD 차단, 재측정·승인 후 재개를 검사한다. 결과는 `OhtFabSetup.result`, `OhtFabPlay.result`에 기록한다.

새 정적 OHT FBX로 다시 설치하면 런타임 참조가 바뀌므로 `OhtFabSetup.once`로 애니메이션도 다시 연결해야 한다.

## 스토커 조작

하단 `스토커` 탭은 수동 출고·입고·일시 정지·내부 보기·스토커 시점을 제공한다. OHT 연속 이송 중에는 수동 출고·입고를 차단한다. OHT의 일시 정지는 스토커 동작에도 적용된다. 슬롯 전체 크기는 유지하며, 한 개 LOT을 슬롯 1에서 출고하고 같은 예약 슬롯으로 입고하는 시연이다. 임의 외부 캐리어의 동적 슬롯 배정은 구현 범위가 아니다.

`StockerPlay.once`는 단독 출고/입고, 일시 정지, 문 인터록, 슬롯 점유/예약과 2mm 정렬, 고정 판넬·선반 및 다른 보관 FOUP의 보수적 경계상자와 이동 부품/FOUP 간 겹침을 검사한다. `OhtFabPlay.once`는 이 흐름을 포함한 전체 공정을 2회 검사한다. 이 검사는 표현 모델의 형상 검사이며 실제 설비의 충돌 인증이나 물리 역학 검증은 아니다.
