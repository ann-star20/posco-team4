# AOI 카메라 → Jetson → Unity

## 현재 연결: IP Webcam (2026-10-24)

스마트폰의 IP Webcam 앱에서 영상 서버를 실행하고 `http://<스마트폰 IP>:<포트>/video`를 Jetson AOI의 카메라 입력 주소로 설정합니다.
스마트폰과 Jetson은 서로 통신 가능한 네트워크에 연결되어 있어야 합니다. 스마트폰 IP가 바뀌면 카메라 입력 주소도 갱신합니다.

- Jetson 기본 주소: `192.168.213.167`
- Unity 영상 연결: `ws://192.168.213.167:8500/camera/preview`
- Unity 검사 연결: `ws://192.168.213.167:8400/aoi`
- Unity는 스마트폰 `/video`에 직접 연결하지 않고 Jetson을 통해 영상과 검사 결과를 받습니다.
- 노트북 웹캠 송출 도구는 현재 IP Webcam 구성에 필요하지 않습니다.

스마트폰 설정은 [SETUP.md](../../docs/SETUP.md#ip-웹캠-연결), Unity 연결과 프레임 검사 규격은 [JETSON_PREVIEW_CONNECTION.md](JETSON_PREVIEW_CONNECTION.md)를 따릅니다.
현재 실서버 연결 성공 여부는 실행 후 별도로 확인해야 합니다.

## 과거 시험·구현 기록

아래 내용은 이전 시험 사진·로컬 소켓·HTTP 방식에 대한 기록입니다. 아래의 예전 주소와 구현 상태 설명은 현재 실행 안내가 아닙니다.


## 직접 WebSocket 사진 수신 시험 (2026-10-19)

### Unity AOI 모니터에서 요청하기

1. Unity에서 Play → 하단 `AOI` → `Jetson 검사 요청 · 모니터 열기`.
2. 확대 창 상단의 `토큰 (숨김)`에 전달받은 `AOI_UNITY_TOKEN`을 입력합니다.
3. `Jetson 검사 시작`을 누릅니다. 직접 연결 주소는 `ws://192.168.11.161:8400/aoi`입니다.
4. 같은 요청 ID의 결과 JSON과 그 뒤 JPEG를 받은 뒤 함께 표시합니다. 토큰은 Play 세션 동안만 보관하며 파일·씬·로그에 쓰지 않습니다.
5. 사진은 다음 요청 또는 모드 변경 전까지 유지합니다. 기존 분류 유효 시간 5초가 지난 과거 결과는 화면에 남아도 분류할 수 없습니다. 새 요청 중 이전 판정은 지웁니다. 자동 분류는 하지 않습니다.

- 현재 입력은 `fixture_name: test_aoi_mosfet1.jpg`인 서버 시험 사진입니다. 실시간 카메라 영상·촬영 요청은 별도입니다.
- 사진의 글자가 아닌 JSON `verdict`로 OK/NG를 표시합니다. `parts`/`defects`의 검출 점수는 불량률이나 검증된 모델 정확도가 아닙니다.
- `result_origin: mock`은 시험 표시를 붙입니다. `prod` 등 다른 출처도 서버가 제공한 값으로 기록·표시하며, 이 값만으로 모델 정확도를 검증한 것은 아닙니다.
- 직접 AOI 통신은 새 `AoiDirectClient`가 담당하며 실행 시 기존 feed에 자동으로 붙습니다. 기존 `/fab` 소켓은 TCAD·공정 분석 메시지를 계속 처리하고 직접 AOI 화면을 덮어쓰지 않습니다.
- 알려지지 않은 불량 라벨은 원문과 검토 필요를 표시하고 분류를 막습니다. 신뢰도 기준을 넘지 않은 결과도 분류하지 않습니다.
- 이전 C# 파일 백업: `Tools/Backups/AoiDirect-20261019-151455`.
- 검증: `test-unity-protocol.ps1`의 ID/해시/메타데이터/판정 모순 검사. `AoiDirectUpgrade.once`는 저장된 JSON/JPEG로 Unity 화면을 재생하는 개발 검사이며 실제 전송이 아닙니다.

- `test-direct-aoi.cmd` 실행 후 팀원이 전달한 토큰을 숨김 입력합니다. 토큰은 저장하지 않습니다.
- 대상: `ws://192.168.11.161:8400/aoi`, 입력 사진: `test_aoi_mosfet1.jpg`.
- `test-direct-aoi.cmd`는 Unity와 별개인 PC 시험 도구입니다. Unity 사용 방법은 위 항목을 따릅니다.
- `aoi.inspection.completed` JSON 뒤에 `binary_frame_follows: true`로 오는 JPEG 바이너리 메시지를 조립합니다.
- 요청 ID/LOT/제품 일치, JPEG 메타데이터, 바이트 수, SHA256과 시작·끝 표식을 확인한 뒤 `DirectTestResults/aoi-<request_id>.jpg`로 저장합니다. 서버가 보낸 파일명·경로는 저장 위치로 사용하지 않습니다.
- 검사 결과와 오류는 같은 폴더의 JSON에 남습니다. `result_origin: mock`은 실제 모델 추론 검증이 아닙니다.
- 사진 수신 성공은 `Status: result_and_image_received`입니다. 시간 초과·연결 종료로 사진이 누락되면 실패로 표시합니다.
- 로컬 회귀 시험: `test_direct_receiver.py` (분할 전송, 해시 불일치, 사진 누락, 다른 요청 결과). 실제 Jetson 사진 수신은 수정 후 재시험이 필요합니다.

## 현재 구현 범위

- 클린룸 AOI의 3D 모니터와 드래그 가능한 `AOI monitor window`는 같은 대시보드를 표시합니다.
- 기본 통신은 이제 로컬 WebSocket 서버입니다. `Tools/FabSocket/README.md`의 Unity 연결 방법을 따릅니다. 아래 HTTP 규격은 이전 호환 경로이며 기본 연결에는 사용하지 않습니다.
- Unity에 연결하는 카메라가 아니라 **젯슨 카메라의 검사 스냅샷**을 표시합니다. 판정과 사진은 한 패킷으로 받습니다. WebSocket에서는 사진 없는 판정도 받을 수 있으며 이미지 미수신을 별도로 표시합니다. 연속 동영상 스트리밍은 아직 없습니다.
- Unity Play 후 기본값은 JETSON 모드/연결 대기입니다. 자동으로 제품을 움직이지 않습니다.
- 신선한 판정이 들어오면 `Start OK / NG sort`로 해당 가상 제품을 분류합니다. 정상은 OK, crash/band/scratch는 NG입니다.
- 낮은 신뢰도, 모르는 라벨, 누락된 사진, 만료·미수신 결과는 분류하지 않습니다.
- 동일 result_id는 같은 세션에서 최근 256건까지 재분류를 차단합니다. 재시작 후 영속 중복 방지는 미구현입니다.
- `Use DEMO`를 누르면 별도로 예시를 선택할 수 있습니다. 그림과 신뢰도는 예시이며 실제 인식이 아닙니다.

## 젯슨 주소

사용자가 알려준 `192.168.55.1:22`는 SSH 주소입니다. 영상 API가 아닙니다.
Unity의 `AoiJetsonFeed.resultUrl`에 **실제로 실행 중인 결과 API**를 입력해야 합니다.
현재 `http://192.168.55.1:8080/aoi/latest`는 연결용으로 예약한 기본 주소이며, 해당 서비스가 젯슨에 설치·실행됐다는 뜻은 아닙니다.

## 제안 수신 규격

`GET /aoi/latest`: HTTP 200, `application/json`, 아래 객체. 결과가 없으면 HTTP 204.

```json
{
  "result_id": "unique-result-000013",
  "product_id": "MOSFET-000013",
  "label": "scratch",
  "confidence": 0.968,
  "captured_at_ms": 1790000000000,
  "jpeg_base64": "<동일 검사 프레임의 JPEG를 base64로 인코딩>"
}
```

- label: `normal`, `crash`, `band`, `scratch`. 학습 모델의 실제 클래스 이름이 다르면 젯슨에서 매핑합니다. `band`는 사용자가 지정한 라벨 그대로입니다.
- confidence: 0–1. 현재 Unity 최소 기준 0.8은 임시 설정으로, 실제 모델 검증 후 변경해야 합니다.
- captured_at_ms: 촬영 시각의 UTC Unix 밀리초. 예제 숫자를 복사하지 말고 촬영 시각을 넣습니다. PC/젯슨 시계를 맞춰야 합니다.
- 기본 유효 시간 5초, 미래 시각 허용 2초. 수동 시작이 늦으면 다시 촬영해야 합니다.
- JPEG는 최대 1920×1080, base64 길이 2,800,000자 이하. 바운딩 박스·불량 유형을 **젯슨에서 그린 영상**을 보내면 그대로 보입니다.
- 결과 ID는 검사마다 새로 만들고, 같은 ID의 결과·이미지는 바꾸지 않습니다.
- 현재 어댑터는 한 번에 한 제품을 수동 검사·분류하는 용도입니다. 분류 중에는 새 결과를 받지 않습니다. 연속 생산용 큐·전달 확인·물리 제품 추적은 후속 작업입니다.

## 아직 필요한 것

라벨링 사진만으로 실시간 인식은 되지 않습니다. 학습한 모델/가중치, 젯슨 추론 실행 코드, 카메라 촬영 코드, 위 결과 API가 필요합니다. 기존 젯슨 코드가 있으면 이 규격에 맞추거나 Unity 수신부를 그 규격에 맞추면 됩니다.

API·실제 젯슨 카메라·실제 학습 모델은 아직 연결 검증하지 않았습니다. Unity의 가상 분류는 물리 장치 제어 명령을 보내지 않습니다.
