# 휴대폰 카메라 연결 준비

Unity에서 Play → AOI 모니터 → **실시간 영상**을 누릅니다.

1. 휴대폰 IP만 입력하면 `http://IP:8080/video`로 연결합니다.
2. 다른 포트나 경로를 쓰면 `http://IP:포트/video` 전체 주소를 입력합니다.
3. 앱에 로그인이 설정되어 있으면 **카메라 아이디·비밀번호**를 입력합니다. 없으면 두 칸을 비웁니다.
4. **연결**을 누릅니다. 같은 버튼에서 설정창을 다시 열고 연결 해제할 수 있습니다.

주소는 이 PC에 저장되며, 다음 Play에서 자동 접속하지 않습니다. 잘못된 주소와 연결 실패는 화면에 표시합니다. 3초 이상 새 화면이 없으면 이전 화면을 숨깁니다. 15초간 데이터를 받지 못하면 연결을 종료합니다. 다시 연결은 사용자가 누릅니다.

## 조건

- 휴대폰 IP Webcam 앱이 실행 중이어야 합니다. PC에서 해당 주소에 접근할 수 있어야 하며 Jetson에 연결되었다는 것만으로 PC 접근이 보장되지는 않습니다.
- Content-Length를 보내는 HTTP/HTTPS MJPEG 스트림과 IP Webcam의 Digest 로그인을 지원합니다. RTSP·H.264·Basic 로그인은 지원하지 않습니다.
- 주소 입력값에 계정·비밀번호·쿼리 토큰은 받지 않습니다. AOI 검사 토큰 입력창은 기존대로 별개입니다.
- 계정은 별도 입력란에서만 받으며 저장하지 않습니다. 연결 시작·설정창 닫기·모니터 닫기·연결 해제 시 입력란을 비웁니다. HTTP 401/403은 로그인 실패로 구분해 표시합니다. 인증은 지정한 카메라의 Digest 요청에만 응답하고 리디렉션은 따라가지 않습니다.
- 프레임 최대 8 MiB, 해상도 최대 4096×4096. 수신은 백그라운드에서 하고 최신 프레임 하나만 보관합니다.
- **영상 표시는 새 AI 검사가 아닙니다.** 우측 OK/NG·불량 위치·이력은 마지막 완료 검사에 대한 결과입니다. 기존 Jetson 검사 요청은 여전히 저장된 시험 사진을 검사합니다. 실시간 카메라 프레임을 검사하려면 Jetson 측 현재 프레임 검사 API를 별도로 연결해야 합니다.

## 검증 및 백업

컴파일, 주소 정규화, 잘못된 주소 거부, 분할 수신, 연속 프레임, 크기 제한을 자동 검사했습니다. 휴대폰 카메라가 작동하지 않아 실제 스트림과 Unity 실행 화면은 미검증입니다.

2026-10-20: 휴대폰이 Digest 인증을 요구하는 HTTP 401을 반환하는 원인을 확인하고 계정 입력을 추가했습니다. 로컬 모의 서버에서 Digest 성공, 비밀번호 오류, Basic 대체 차단, 리디렉션 차단, 다른 호스트로의 계정 전달 차단 검사를 통과했습니다. 실제 휴대폰 계정으로 영상이 표시되는지는 사용자 직접 입력 후 확인해야 합니다. 인증 수정 전 백업은 `Tools/aoi-camera-auth-backup.txt` 참조. 해당 백업의 AoiDashboard.cs와 AoiCameraStream.cs를 복원하면 됩니다.
