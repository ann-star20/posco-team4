# 설비별 시작 버튼의 OHT 투입

Play 중 OhtFabCycle이 있는 장면에서 설비별 시작 버튼은 공정 순서대로 앞 설비의 FOUP를 이어받는다.

| 시작 버튼 | FOUP 출발 위치 |
|---|---|
| 산화로 Start/Restart | 스토커 |
| 앨립소미터 Start scan | 산화로·로딩 완료 투입구 |
| 이온주입기 Start implant | 정상 앨립소미터 검사 완료 투입구 |

1. OHT·설비·스토커의 사용 가능 상태 확인. 사용 중에는 중복 출발하지 않으며 준비 후 다시 시작한다.
2. 새 LOT는 산화로 시작에서만 준비한다. 다음 설비는 같은 LOT·웨이퍼를 이어받고, 앞 공정 미완료 시 대기한다. 선택한 검사에 필요한 CSV 입력을 확인한다.
3. 산화로는 스토커 Dispatch → Pick(0), 앨립소미터는 산화로 Pick(1), 이온주입기는 앨립소미터 Pick(2) 후 선택한 설비로 Travel/Place.
   OHT가 이미 해당 정차 위치에 있으면 빈 차로 한 바퀴 돌지 않고 즉시 하강·집기를 시작한다. 다른 정차 위치까지의 이동은 기존 레일 방향을 유지한다.
4. 투입 완료 후 선택한 설비만 Process. OHT가 내부에서 부르는 Start는 재출고 요청으로 재귀하지 않는다.
5. 산화 완료 FOUP와 정상 산화막 검사 FOUP는 다음 설비 시작 전까지 투입구에 남는다. NG·TCAD 검토 대상은 스토커 격리하고 이온주입기로 넘기지 않는다. 예측 대기 건은 확인 후 진행하며, 늦게 NG가 수신되면 격리한다. 이온주입 완료는 기존 ReturnHeld 및 정상 자동 출고/NG HOLD·비동기 TCAD 흐름을 유지한다.

전체 공장 OHT StartCycle의 공정 순서는 유지한다. OHT가 없는 장면 및 Editor의 직접 Cycle 재생은 기존 설비 동작을 사용한다.

## 확인

검사 결과는 SingleToolOht.result에 기록한다. 실제 Unity Play에서 공개 시작 버튼으로 같은 LOT의 순차 이송, 완료 위치 유지, NG 격리와 잘못된 시작 순서 차단을 검사한다.
시험 CSV fixture를 사용했고 Gateway를 해제한 상태였다. 실제 서버 검사 요청을 전송한 검사는 아니다.
